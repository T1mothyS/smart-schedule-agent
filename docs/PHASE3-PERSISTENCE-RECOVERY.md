## 保存与恢复协议

### 单库

每次完整导出写入同目录 `.pending-*` 文件，权限按 0600 创建，刷新文件后替换 live 文件。Linux 等支持的平台额外刷新父目录；Windows 的 Node 不支持同样的目录刷新，本轮不声称覆盖断电或存储设备缓存故障。异常发生在替换之后时，以实际 live 文件重新建立内存；因此调用方应以错误和重读状态为准，不能把任何异常都解释为“绝未落盘”。

### 同步跨库提交

withPersistenceTransaction 仅用于同步回调，不允许 await/网络调用。回调中的 store 保存先登记待写文件；提交前将旧完整镜像写入 `data/.persistence-undo.json`，随后替换涉及的数据库，最后删除恢复记录。提交成功前不返回业务成功响应。

- 进程中断且记录仍在：下次初始化先恢复旧镜像，再打开数据库。
- 正常捕获失败：回退内存并用记录恢复磁盘；补偿仍失败时保留记录，阻止查询/保存，等待磁盘修复与重启。
- 记录内容异常、路径不合法或数据库头不正确：拒绝启动。
- 当前仍要求一个进程拥有四库；这不是多进程并发数据库协议，也不提供分布式事务。

### 全站恢复

要求 `MAINTENANCE_MODE=true`，且 `BACKGROUND_JOBS_ENABLED` 不为 true；应在关闭后台任务后重启进入维护流程。原确认文字与加密校验保留。切换前保存 `data/.system-restore.json`，列明允许的数据库/附件/媒体目标和旧副本位置。启动恢复使用可重复复制，保留恢复源，避免第二次中断消耗唯一副本。成功切换后旧内存禁止写入，API 沿用 restartRequired 和退出重启行为。

自动恢复后可能保留 `.pre-restore-*` 副本供检查；不要为清理目录直接删除唯一恢复来源。用户恢复中断可能留下没有元数据引用的新附件文件，但不会提前删除旧附件。

### AI 重试合同

AI 输入仍只生成待确认草稿。已确认操作按账号和稳定 plan/import ID 重放持久结果；部分失败也重放同一结果，修正失败项目需生成/确认新计划，不能重跑整个旧计划。替换用户数据、清空账号数据和删除账号会清除该账号旧执行结果，避免回放不再存在的数据。新建表不改变旧表字段或备份版本。

## 未验证与残余风险

- 未执行 Linux 文件系统实测：本机没有可用 WSL Linux 环境；未安装系统组件。CI Node 22、全新 npm ci、Electron 实机与生产业务未验证。
- 进程中断测试不等于断电、硬盘控制器缓存或网络文件系统测试。Windows 原子替换仍可能因文件占用失败，此时回退/拒绝成功并保留旧数据。
- 同步事务会复制完整数据库镜像；较大数据库会增加内存和磁盘开销。仍需保留足够空间，2GB 生产部署前应核对真实数据规模，但本轮不读取生产数据库。
- 用户备份仍不携带日报媒体二进制；缺图明确返回 PARTIAL，跨机器完整媒体迁移需要系统快照或另行复制并验收。
- 没有自动修补历史上已形成的不一致记录；本轮阻止新故障路径。未包装的其他多步业务不是自动事务。

## 回滚与故障处理

运行时记录含数据库内容，属于敏感数据；已被 .gitignore 排除，不上传日志/报告。磁盘故障后先停止服务并保留整个 data 及恢复记录，在修复存储后用本版本启动完成恢复，再检查业务。不要直接删除恢复记录来绕过启动保护。

代码按本地 checkpoint 分项保存。需要降级时先停后台任务、保存四库与文件快照、完成待恢复记录，并检查已确认计划；旧版本不识别执行结果表或恢复记录，直接降级可能重新引入重复确认窗口。不得把代码 revert 当作已经损坏的数据修复。

## 简短 premortem

1. 数据增长导致事务快照占满磁盘：同目录替换、旧镜像和拒绝成功降低损坏风险；仍需容量监测，不能消除内存/磁盘上限。
2. 后续开发在事务回调中加入异步或新跨库分支：当前同步边界、保存点和故障测试提供约束；未接入编排的业务仍需单独验证。
3. 操作者删除恢复记录或在旧版本启动：启动拒绝不完整记录、保留副本并文档化降级步骤；手工破坏恢复来源仍无法自动修复。
